## Nav — solid header, and the drawer must NEVER live inside `<header>` (2026-07-27, client iOS bug)
Two rules, both load-bearing:
- **`Nav.jsx` returns a fragment**: `<header class="nav">` and the `#mobile-menu` drawer are SIBLINGS. The drawer is `position: fixed; inset: 68px 0 0 0`, and any ancestor with `backdrop-filter`/`filter`/`transform` becomes the containing block for fixed descendants — Safari/WebKit honours this, Blink doesn't. Inside the 68px header the drawer computed to **height 0** on iPhone: background invisible, links spilling over the live page (client screenshots, iPhone 16 Pro Max; Android was fine). Don't move it back in, and don't put a filter/transform on any ancestor of it.
- **The nav is opaque, never frosted**: `.nav.scrolled` (and `.nav.menuOpen`, so an open menu at scroll 0 doesn't show the hero through the bar) is a flat `background: var(--bg)` with no `backdrop-filter` in either ink mode — client called the old `rgba(…, .78)` + blur "see through". The unscrolled bar stays transparent over the hero on purpose.
- Supporting details: the drawer is `overflow-y: auto` + `overscroll-behavior: contain` with `max(32px, env(safe-area-inset-bottom))` bottom padding (short landscape phones and the iOS URL bar clipped the footer row), and `BackToTop` sits at `--z-nav - 2` — it used to tie with the drawer at 99 and, being later in the DOM, floated over the open menu.

## Typography — Satoshi weight lives in the FAMILY, never `font-weight` (2026-07-22, user rule)
Each Satoshi OTF is registered as its own single-face family (`'Satoshi Light' / 'Satoshi Regular' / 'Satoshi Medium' / 'Satoshi Bold' / 'Satoshi Black'`, each declared `font-weight: 100 900` so an inherited or UA weight — e.g. the browser's default bold on `h1` — can never trigger a synthesized face). Call sites pick a face through the tokens `--f-display-light / -reg / -med / -bold / -black` and **declare no `font-weight` at all**. The composite `'Satoshi'` family (300–900 + italics) stays registered for legacy fallback chains only. The sweep converted all 85 Satoshi weight call sites plus `reset.css` (`h1/h2` Black, `h3` Bold, `h4` Medium). **Inter / Inter Tight still use `font-weight`** — they're loaded from Google Fonts and there are no local files to split per weight; self-hosting them per-weight is the logged follow-up in `tasks/todo.md`.

Nav items (`.link`) run `--f-nav` (= `--f-display-med`); the mobile drawer links run `--f-display-bold`. The header must read Satoshi on every route.

## Conventions
- One CSS module per component file. Class names locally scoped.
- Tokens come from `styles/tokens.css`. Don't hardcode hex outside tokens (exceptions: traffic-light dots, code syntax colors).
- Single accent (`--accent: #5B5BFF`). No second accent. No gold. No warm cream.
- `prefers-reduced-motion` honored everywhere: tokens collapse animation durations to `0ms`, `Reveal`/`KineticText` fall through (MotionConfig `reducedMotion="user"`), scroll-linked values gate via `reduced ? 1 : value`, per-module `@media (prefers-reduced-motion: reduce)` kills hover transitions.
- All animations are GPU-friendly (`transform` / `opacity` only). Never animate `width/height/top/left/padding/margin`.
- Touch targets ≥ 44×44px. `min-height: 44px` on buttons, hamburger 44×44, mobile nav links min-height 56px.
- Focus rings: custom indigo ring via `--focus-ring`. Never `outline: none` without a visible alternative.
- Semantic HTML: `<header>` for nav, `<main>` for main content, `<section>` per logical section, `<article>` for portfolio cards, `<footer>`.
- Skip-link at top of `App` for keyboard users.

## BackToTop — floating scroll-to-top control (2026-07-22)
`src/components/BackToTop.jsx` + `.module.css`, mounted after `<Footer />` in `App.jsx`. A 48px glass disc (44px ≤640px, safe-area insets) pinned bottom-right at `calc(var(--z-nav) - 1)` so the nav always wins. It carries a **live scroll-progress ring** — an SVG circle whose `stroke-dashoffset` tracks `scrollY / (scrollHeight - innerHeight)` from a rAF-throttled scroll+resize listener — and fades/rises in only past `0.9 × innerHeight` (hidden state also drops it from the tab order via `tabIndex={-1}` + `aria-hidden`). Hover slides the arrow up out of a 16px clip box while an identical arrow rises in behind it. Click scrolls through `getLenis()` (`duration: 1.1`, 0 under reduced motion) with a native `window.scrollTo` fallback — never `scrollIntoView`, which Lenis's rAF loop cancels. Tokens only, so both ink modes adapt; the RM block kills every transition.
